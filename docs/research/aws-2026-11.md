### 1.5 Soporte de MCP y A2A

- **MCP**: Runtime hospeda servidores MCP (puerto 8000, ruta `/mcp`, stateless y stateful); soporta la versión de protocolo **`2026-07-28`** (nov-2026). Gateway **es** un servidor MCP (`https://<gateway-id>.gateway.bedrock-agentcore.<region>.amazonaws.com/mcp`) y agrega servidores MCP remotos como targets; soporta MCP Tasks (`io.modelcontextprotocol/tasks`). Strands consume MCP con `MCPClient`.
- **A2A**: Runtime hospeda servidores A2A (puerto 9000, raíz `/`, Agent Card en `/.well-known/agent-card.json`). Gateway hace passthrough HTTP hacia agentes A2A. Strands: `A2AAgent` (cliente) y `A2AServer` (servidor), extra `strands-agents[a2a]`.
- **AG-UI**: cuarto protocolo de Runtime (puerto 8080, `/invocations` SSE o `/ws`), desde mar-2026.

### 3.2 Agente mínimo con un `@tool` (https://strandsagents.com/docs/user-guide/sdk/quickstart/python/)

```python
from strands import Agent, tool
from strands.vended_tools import file_editor

@tool
def letter_counter(word: str, letter: str) -> int:
    """
    Count occurrences of a specific letter in a word.

    Args:
        word (str): The input word to search in
        letter (str): The specific letter to count

    Returns:
        int: The number of occurrences of the letter in the word
    """
    if len(letter) != 1:
        raise ValueError("The 'letter' parameter must be a single character")
    return word.lower().count(letter.lower())

agent = Agent(tools=[letter_counter, file_editor])   # Bedrock por defecto
agent('How many letter R\'s are in the word "strawberry"? Write the answer to answer.txt.')
```
- Ejecutar: `python -u agent.py`. El docstring y los type hints son lo que lee el modelo.
- Cada invocación devuelve un `AgentResult` (mensajes, métricas, trazas; `result.message`, `result.stop_reason`). Para silenciar el streaming a consola: `Agent(callback_handler=None)`.
- Credenciales Bedrock: `AWS_BEARER_TOKEN_BEDROCK`, o `aws configure` / `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` (+ `AWS_SESSION_TOKEN`), o rol IAM.
- Modelo por string: `Agent(model="global.anthropic.claude-sonnet-5", system_prompt="...")` (así aparece en la doc de trazas).

### 3.4 Agent loop, stop reasons y límites (https://strandsagents.com/docs/user-guide/sdk/agents/agent-loop/)

El loop: el prompt y el historial van al modelo; mientras el modelo pida tools, el agente las ejecuta y devuelve resultados; cuando no hay más tool calls, el mensaje es la respuesta. `stop_reason` posibles (Python): `end_turn`, `tool_use`, `max_tokens`, `guardrail_intervened`, `interrupt`, `cancelled`, `limit_turns`, `limit_total_tokens`, `limit_output_tokens`, `limit_structured_output_attempts`.

```python
result = agent(
    "Summarize this document",
    limits={"turns": 5, "output_tokens": 2000, "total_tokens": 10000},
)
if result.stop_reason == "limit_turns":
    print("Hit turn budget")
```
Los límites se evalúan al inicio de cada iteración (un turno puede pasarse) y aplican solo a esa invocación.

### 3.5 Streaming y forma real de los eventos (https://strandsagents.com/docs/user-guide/sdk/streaming/events/)

```python
import asyncio
from strands import Agent

agent = Agent(callback_handler=None)

async def main():
    async for event in agent.stream_async("Tell me about agents in one sentence."):
        if "data" in event:
            print(event["data"], end="", flush=True)

asyncio.run(main())
```
En Python los eventos son **diccionarios planos**. Claves documentadas:
- Ciclo de vida: `init_event_loop`, `start_event_loop`, `event_loop_throttled_delay`, `message`, `event` (evento crudo del modelo), `force_stop` (+ `force_stop_reason`), `result` (el `AgentResult` final).
- Modelo: `data` (trozo de texto), `delta`, `reasoning` (+ `reasoningText`, `reasoning_signature`, `redactedContent`).
- Tools: `current_tool_use` (`toolUseId`, `name`, `input`), `tool_stream_event` (`tool_use`, `data`).
- Multiagente (campo `type`): `multiagent_node_start`, `multiagent_node_stream`, `multiagent_node_stop`, `multiagent_handoff`, `multiagent_result`.

En TypeScript son clases con `type` (`modelStreamUpdateEvent` → `modelContentBlockDeltaEvent` → `textDelta`): `for await (const event of agent.stream('...'))`.

### 3.6 Hooks (https://strandsagents.com/docs/user-guide/sdk/agents/hooks/)

```python
from strands import Agent
from strands.hooks import BeforeInvocationEvent, BeforeToolCallEvent

agent = Agent()

def typed_callback(event: BeforeToolCallEvent) -> None:
    print(f"Tool called: {event.tool_use['name']}")

agent.add_hook(typed_callback)   # el tipo de evento se infiere del type hint
```
Eventos: `AgentInitializedEvent`, `BeforeInvocationEvent`, `AfterInvocationEvent`, `MessageAddedEvent`, `BeforeModelCallEvent`, `AfterModelCallEvent`, `BeforeToolsEvent`, `AfterToolsEvent`, `BeforeToolCallEvent`, `AfterToolCallEvent`; multiagente: `BeforeNodeCallEvent`, `AfterNodeCallEvent`, `BeforeMultiAgentInvocationEvent`, `AfterMultiAgentInvocationEvent`, `MultiAgentInitializedEvent`. ### 3.11 Human-in-the-loop: interrupts (https://strandsagents.com/docs/user-guide/sdk/interrupts/)

```python
from strands import Agent, tool
from strands.hooks import BeforeToolCallEvent, HookProvider, HookRegistry

class ApprovalHook(HookProvider):
    def register_hooks(self, registry: HookRegistry, **kwargs) -> None:
        registry.add_callback(BeforeToolCallEvent, self.approve)

    def approve(self, event: BeforeToolCallEvent) -> None:
        if event.tool_use["name"] != "delete_files":
            return
        approval = event.interrupt("myapp-approval", reason={"paths": event.tool_use["input"]["paths"]})
        if approval.lower() != "y":
            event.cancel_tool = "User denied permission to delete files"

agent = Agent(hooks=[ApprovalHook()], tools=[delete_files], callback_handler=None)
result = agent("Delete a/b/c.txt")
while result.stop_reason == "interrupt":
    responses = [{"interruptResponse": {"interruptId": i.id, "response": input(f"{i.reason} (y/N): ")}}
                 for i in result.interrupts]
    result = agent(responses)
```
Interrumpibles: `BeforeToolCallEvent` (una tool) y `BeforeToolsEvent` (el lote; `event.cancel = "..."`). Desde una tool: `@tool(context=True)` y `tool_context.interrupt("nombre", reason={...})`. Existe además la capa "Interventions" (aprobación humana configurable) y la vended tool `handoff-to-user`.

```python
## app/StrandsClaude/main.py
from strands import Agent, tool
from strands_tools import calculator
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands.models import BedrockModel

@tool

    """Get weather"""

    user_input = payload.get("prompt")
```

### 4.4 Qué se crea

- `agentcore deploy` usa AWS CDK y CloudFormation. Stack: `AgentCore-<project-name>-<target-name>`; requiere el stack `CDKToolkit` (bootstrap). El primer deploy tarda minutos.
- **CodeZip** (plantilla por defecto): paquete zip, sin Docker ni ECR. **Contenedor**: CDK sube el código y **AWS CodeBuild** construye la imagen y la sube a **Amazon ECR**.
- Rol de ejecución: trust policy con principal `bedrock-agentcore.amazonaws.com` (condiciones `aws:SourceAccount` y `aws:SourceArn` = `arn:aws:bedrock-agentcore:<region>:<account>:*`).
- Formato de ARN (ejemplos de la doc): `arn:aws:bedrock-agentcore:us-west-2:123456789012:runtime/TripPlanner_default_agent-PGgpqs8dg5`; memory: `…:memory/TripPlanner_default_agentMemory-ONPlNgHMeg`; gateway: `…:gateway/my-gateway-a1b2c3d4e5`; harness: `…:harness/MyHarness-XyZ1234567`.
- Versiones inmutables (V1 al crear; cada cambio de config crea otra) y endpoints: `DEFAULT` se crea solo y apunta a la última versión; endpoints propios con `CreateAgentRuntimeEndpoint`. Estados: `CREATING`, `CREATE_FAILED`, `READY`, `UPDATING`, `UPDATE_FAILED`.
- Log groups: `/aws/bedrock-agentcore/runtimes/<agent_id>-<endpoint_name>`.

API directa (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-how-it-works.html):

### 4.5 Sesiones, duración y límites (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-sessions.html y `bedrock-agentcore-limits.html`)

- Cada sesión (`runtimeSessionId`) corre en su **propia microVM** con CPU, memoria y filesystem aislados; al terminar, la microVM se destruye y la memoria se sanea.
- `runtimeSessionId`: **mínimo 33 caracteres** (usa un UUID). AgentCore **no** valida la relación usuario↔sesión: es tarea de tu backend.
- Estados: Active, Idle, Stopped. Idle timeout **15 min** (`idleRuntimeSessionTimeout`, 60–28800 s, default 900). Vida máxima **8 horas** (`maxLifetime`, default 28800). En **Instances**: hasta **14 días**.
- Estado efímero por defecto; para persistir: *session storage* (1 GB por sesión) o AgentCore Memory.
- Límites: timeout de petición síncrona **15 min**; payload **100 MB**; chunk de streaming 10 MB; streaming máx. 60 min; job asíncrono 8 h (microVM); frame WebSocket 64 KB.
- Hardware por sesión: **2 vCPU / 8 GB** por defecto; hasta 8 vCPU / 32 GB con *resource configurations* (V2).
- Imagen Docker: 2 GB (V1) / 10 GB (V2). CodeZip: 250 MB comprimido, 750 MB descomprimido. Variables de entorno: 4 KB.
- Cuotas: sesiones activas 5.000 (us-east-1, us-west-2) / 2.500 (resto); 1.000 agentes por cuenta; 10 endpoints por agente; data plane 1.000 TPS; creación de sesiones 25 TPS.
- Headers de sesión: HTTP/A2A/AG-UI `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id`; MCP `Mcp-Session-Id`.
- **Platform version V2**: arranca desde un snapshot (cold starts consistentes); crear/actualizar tarda minutos; el contenedor debe responder sano en `/ping` en 120 s; disponible en 19 regiones. Con V2, crea los clientes boto3 **dentro** del handler (`boto3.Session()`), no a nivel de módulo, para que carguen las credenciales de la sesión.

### 4.6 Invocar desde boto3 (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-invoke-agent.html)

```python
import boto3, json, uuid

agent_core_client = boto3.client('bedrock-agentcore')
response = agent_core_client.invoke_agent_runtime(
    agentRuntimeArn="arn:aws:bedrock-agentcore:us-west-2:123456789012:runtime/MyProject_default_agent-XXXXXXXXXX",
    runtimeSessionId=str(uuid.uuid4()),          # ≥ 33 caracteres; repetir para continuar la conversación
    payload=json.dumps({"prompt": "What is 2 + 2?"}).encode(),
    qualifier="DEFAULT",                          # opcional: endpoint
)

if "text/event-stream" in response.get("contentType", ""):
    for line in response["response"].iter_lines(chunk_size=10):
        if line:
            line = line.decode("utf-8")
            if line.startswith("data: "):
                print(line[6:])
elif response.get("contentType") == "application/json":
    print(json.loads(''.join(chunk.decode('utf-8') for chunk in response.get("response", []))))
```
- Respuesta: `contentType` + `response` (stream). Permiso: `bedrock-agentcore:InvokeAgentRuntime`.
- Si el runtime usa OAuth (JWT) **no** puedes usar el SDK de AWS: haz HTTPS directo a `https://bedrock-agentcore.{region}.amazonaws.com/runtimes/{ARN_ESCAPADO}/invocations?qualifier=...` con el bearer token.
- Errores: `ValidationException` 400, `AccessDeniedException` 403, `ResourceNotFoundException` 404, `RetryableConflictException` 409 ("Session operation in progress, please retry"), `RuntimeClientError` 424 (tu contenedor devolvió 4xx/5xx: mira CloudWatch), `ThrottlingException` 429, `ServiceQuotaExceededException` 402.
- Comandos de shell en la misma sesión: `InvokeAgentRuntimeCommand`.

## 5. Memory, Gateway, Identity, Policy, Observability, Evaluations

### 5.1 Memory (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-get-started.html)

- **Corto plazo**: eventos crudos por `actorId` + `sessionId` (API `CreateEvent`, `ListEvents`, `GetEvent`, `ListSessions`). Retención de eventos hasta 365 días (default del asistente del CLI: 30 días; mínimo: ver "A confirmar").
- **Largo plazo**: registros extraídos de forma **asíncrona** por *estrategias* (extracción + consolidación). Estrategias del CLI: `SEMANTIC`, `USER_PREFERENCE`, `SUMMARIZATION`, `EPISODIC` (en la API: `semanticMemoryStrategy`, `summaryMemoryStrategy`, …). Máximo 6 estrategias por memoria. APIs: `RetrieveMemoryRecords` (búsqueda semántica), `ListMemoryRecords`, `GetMemoryRecord`; ingesta directa `IngestData`.
- **Namespaces**: plantillas jerárquicas con `/` inicial y final y variables `{actorId}`, `{sessionId}`, `{memoryStrategyId}`; ej. `/strategy/{memoryStrategyId}/actor/{actorId}/session/{sessionId}/`. Hasta 5 variables custom (`namespaceKeys`, en minúsculas) pasadas en `extractionConfig.namespaceVariables` de `CreateEvent`.
- Solo se procesan a largo plazo los eventos guardados **después** de que la estrategia esté `ACTIVE`.

```bash

agentcore status --json               # ARN; el id es lo que sigue a "memory/"
agentcore memory get --id <memory-id> # estado ACTIVE
agentcore memory event list --id <memory-id> --actor-id <actor-id> --session-id <session-id>
agentcore memory record list --id <memory-id> --namespace-path /
```

### 5.2 Gateway (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-quick-start.html)

Tres categorías de targets:
- **MCP targets** (modo agregación: un servidor MCP virtual único): funciones **Lambda**, etapas de **API Gateway REST**, esquemas **OpenAPI**, modelos **Smithy**, **servidores MCP** remotos, plantillas de integración (Salesforce, Slack, JIRA, Zoom…) y connectors integrados (Web Search Tool, Step Functions…).
- **HTTP targets** (passthrough, sin traducción): agentes de AgentCore Runtime, otros agentes (A2A), servidores MCP externos, cualquier HTTP.
- **Inference targets**: enrutan tráfico LLM a proveedores según el campo `model` (Bedrock, OpenAI, Anthropic); con fallback de modelo.

Auth **entrante** (authorizer): JWT (`CUSTOM_JWT`), IAM (SigV4, `AWS_IAM`), *authenticate only* y `NONE` (solo desarrollo). Auth **saliente**: rol de servicio del gateway (IAM/SigV4; Lambda y Smithy), OAuth client o API key vía credential provider de Identity (OpenAPI, MCP). 3LO para MCP targets GA desde abr-2026.

**Búsqueda semántica de tools**: si se habilita al crear el gateway, existe la tool `x_amz_bedrock_agentcore_search` (argumento `query`). Nombres de tools: `<TargetName>___<tool>` (tres guiones bajos).

```bash
agentcore create --name MyGatewayProject --template empty && cd MyGatewayProject
agentcore add gateway --name TestGateway --authorizer-type NONE
agentcore add gateway-target --gateway TestGateway --target-configuration '{
    "name": "TestLambdaTarget",
    "targetType": "lambdaFunctionArn",
    "lambdaFunctionArn": {"lambdaArn": "<YOUR_LAMBDA_ARN>", "toolSchemaFile": "tools.json"}
  }'
agentcore deploy
agentcore invoke --gateway TestGateway --path /mcp \
  --payload '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```
Handler Lambda de ejemplo: el nombre de la tool llega en `context.client_context.custom["bedrockAgentCoreToolName"]` (`tool_name.split("___", 1)[1]`). URL: `https://<gateway-id>.gateway.bedrock-agentcore.<region>.amazonaws.com/mcp`. Consumo desde Strands:
```python
from strands import Agent
from strands.tools.mcp.mcp_client import MCPClient
from mcp.client.streamable_http import streamablehttp_client

mcp_client = MCPClient(lambda: streamablehttp_client(gateway_url, headers={"Authorization": f"Bearer {token}"}))
with mcp_client:
    tools = mcp_client.list_tools_sync()     # paginar con pagination_token si hay muchas
    agent = Agent(tools=tools)
```
Cuotas: 100 targets por gateway, 1.000 tools por target, timeout 15 min, payload 6 MB. Precio: $0.005 por 1.000 invocaciones; Search API $0.025 por 1.000; indexado $0.02 por 100 tools/mes; Web Search $7.00 por 1.000 consultas.

### 5.3 Identity (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html)

- Las identidades de agente son **workload identities** (directorio `workload-identity-directory/default`). El runtime obtiene un *workload access token* (`GetWorkloadAccessToken`, `…ForJWT`, `…ForUserId`).
- **Inbound**: IAM (SigV4) u OAuth 2.0/JWT con Discovery URL, Allowed Audiences y Allowed Clients (Cognito, Okta, Microsoft Entra ID, Auth0…).
- **Outbound**: credential providers OAuth2 y API key guardados en el **token vault**; el agente nunca ve secretos de larga duración ni refresh tokens. Modos: *user-delegated* (3LO, `USER_FEDERATION`) y *autonomous* (2LO, `M2M`).

```python
from bedrock_agentcore.identity.auth import requires_access_token, requires_api_key

@requires_access_token(
    provider_name="google-provider",
    scopes=["https://www.googleapis.com/auth/drive.metadata.readonly"],
    auth_flow="USER_FEDERATION",          # 3LO; "M2M" para máquina a máquina (2LO)
    on_auth_url=lambda x: print("\nPlease copy and paste this URL in your browser:\n" + x),
    force_authentication=False,
    callback_url='insert_oauth2_callback_url_for_session_binding',
)
async def write_to_google_drive(*, access_token: str):
    pass   # usa el token
```
(https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-authentication.html). Precio: $0.010 por 1.000 tokens o API keys pedidos; **sin costo** si se usa a través de Runtime o Gateway.

### 5.4 Policy (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-getting-started.html)

- Un **policy engine** (colección de políticas) se adjunta a un Gateway e intercepta cada tool call fuera del código del agente. Modo `ENFORCE`: **deny por defecto**, y `forbid` gana sobre `permit`. Decisiones registradas en CloudWatch.
- Principales: `AgentCore::OAuthUser` (claim `sub` del JWT; tags con claims) y `AgentCore::IamEntity`.
- Lenguajes: **Cedar** y **Dogwood** (superset de Cedar; la doc dice "Write Dogwood"). Generación desde lenguaje natural con `agentcore gateway policy generate`.
- Bedrock Guardrails dentro de políticas: evalúa entradas a targets y salidas de tools en el gateway.

```bash
agentcore add policy-engine --name RefundPolicyEngine --attach-to-gateways PolicyGateway --attach-mode enforce
agentcore deploy                                   # primero el gateway: la política necesita su ARN
agentcore add policy --name RefundLimit --engine RefundPolicyEngine --statement file://refund_policy.cedar
agentcore deploy
```
```cedar
permit(principal,
  action == AgentCore::Action::"RefundTarget___process_refund",
  resource == AgentCore::Gateway::"<gateway-arn>")
when {
  context.input.amount < 1000
};
```
El servicio rechaza recursos comodín (`permit(principal, action, resource);`). Validación por defecto `FAIL_ON_ANY_FINDINGS` (`--validation-mode ignore-all-findings` para solo esquema). Precio: $0.000025 por petición de autorización; generación $0.13 por 1.000 tokens de input.

### 5.5 Observability (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-get-started.html)

- Todo va a **Amazon CloudWatch** en formato OpenTelemetry. Requisito único por cuenta: **CloudWatch Transaction Search** (`agentcore deploy` lo activa solo; opt-out `agentcore config transactionSearch false`). Tras activarlo, los spans tardan hasta 10 minutos en aparecer.
- Agentes en Runtime desplegados con el CLI: instrumentación OTel automática.
- Agentes fuera de Runtime: `aws-opentelemetry-distro` (ADOT) + framework con trazas (`strands-agents[otel]`) y:
```bash
export AGENT_OBSERVABILITY_ENABLED=true   # Activates the ADOT pipeline
export OTEL_PYTHON_DISTRO=aws_distro
export OTEL_PYTHON_CONFIGURATOR=aws_configurator
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_LOGS_HEADERS=x-aws-log-group=<YOUR-LOG-GROUP>,x-aws-log-stream=<YOUR-LOG-STREAM>,x-aws-metric-namespace=<YOUR-NAMESPACE>
export OTEL_RESOURCE_ATTRIBUTES=service.name=<YOUR-AGENT-NAME>
opentelemetry-instrument python agent.py
```
- Correlación de sesión: `from opentelemetry import baggage, context` y `ctx = baggage.set_baggage("session.id", session_id)`.
- Métricas en el namespace `bedrock-agentcore`; logs en `/aws/bedrock-agentcore/runtimes/<agent_id>-<endpoint_name>`; spans en el stream `spans` de ese log group o en `aws/spans`.
- Precio: según Amazon CloudWatch.

### 5.6 Evaluations (https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/evaluations.html)

- LLM-as-a-Judge sobre sesiones, trazas y spans (Strands, LangGraph; OpenTelemetry u OpenInference). Evalúa agentes dentro **o fuera** de Runtime.
- Tipos: **online** (monitoreo continuo con muestreo), **on-demand** (spans/trazas concretos), **batch**, **dataset** (preview), simulación.
- Evaluadores built-in con id `Builtin.<Nombre>`: `Builtin.Helpfulness`, `Builtin.GoalSuccessRate`, `Builtin.Correctness`, `Builtin.ToolSelectionAccuracy`… (13 al momento de la GA). ARN: `arn:aws:bedrock-agentcore:::evaluator/Builtin.Helpfulness`. Custom: LLM o código (Lambda).
```bash
agentcore add online-eval --name "your_config_name" --agent "your_runtime_name" \
  --evaluators "Builtin.GoalSuccessRate" "Builtin.Helpfulness" --sampling-rate 1.0 --enable-on-create true
agentcore deploy
agentcore eval online-eval list
agentcore eval online-eval pause --id <ONLINE_EVAL_ID>
```
Precio: built-in $2.40 / $12.00 por 1M de tokens input/output (batch $1.80 / $9.00); custom $1.50 por 1.000 evaluaciones más el uso del modelo.

## 6. Bedrock Guardrails

Tipos de política (https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html):
1. **Content filters**: Hate, Insults, Sexual, Violence, Misconduct y **Prompt Attack**; fuerza configurable por categoría; texto e imágenes.
2. **Denied topics**: temas definidos en lenguaje natural.
3. **Word filters**: palabras/frases custom y lista de profanidad.
4. **Sensitive information filters**: PII (bloquear o enmascarar) y regex custom.
5. **Contextual grounding checks**: grounding y relevancia (RAG).
6. **Automated Reasoning checks**: valida respuestas contra reglas lógicas.

*Tiers* (content filters, prompt attacks, denied topics, contextual grounding): **Standard** (más robusto, más idiomas, detecta contenido dañino dentro de código, usa cross-Region inference) y **Classic** (inglés, francés y **español**).

**Prompt attack filter**: detecta *jailbreaks*, *prompt injection* y *prompt leakage* (este último solo en Standard). Con `InvokeModel` debes etiquetar el input del usuario con tags `<amazon-bedrock-guardrails-guardContent_xyz>`; sin tags no se filtra. **No evalúa resultados de tools** (`messages[].content[].toolResult`) ni definiciones de tools: no protege contra inyección indirecta vía tools (para eso: Guardrails en AgentCore Policy/Gateway).

Formas de aplicar:
- En línea: Converse/InvokeModel con id y versión del guardrail (solo en `bedrock-runtime`; Mantle no soporta Guardrails). Existe un borrador de trabajo (`DRAFT`) y versiones numeradas.
- **ApplyGuardrail** (sin invocar modelo; sirve para cualquier modelo):
```python
import boto3
bedrock = boto3.client("bedrock-runtime", "us-west-2")
response = bedrock.apply_guardrail(
    guardrailIdentifier="your-guardrail-id",
    guardrailVersion="1",
    source="INPUT",                       # "OUTPUT" para la respuesta del modelo
    content=[{"text": {"text": "texto a evaluar"}}],
)
if response.get("action") == "GUARDRAIL_INTERVENED":
    ...
```
REST: `POST /guardrail/{guardrailIdentifier}/version/{guardrailVersion}/apply`. Respuesta: `action` (`GUARDRAIL_INTERVENED` | `NONE`), `actionReason`, salidas (texto enmascarado o mensaje configurado), `assessments[]` (`topicPolicy`, `contentPolicy`, `wordPolicy`, `sensitiveInformationPolicy`, `contextualGroundingPolicy`, `invocationMetrics`) y `usage`.
- En **Strands** (https://strandsagents.com/docs/user-guide/sdk/safety-security/guardrails/):
```python
from strands import Agent
from strands.models import BedrockModel

bedrock_model = BedrockModel(
    model_id="global.anthropic.claude-sonnet-5-5",
    guardrail_id="your-guardrail-id",
    guardrail_version="1",
    guardrail_trace="enabled",              # "enabled" | "disabled" | "enabled_full"
    guardrail_redact_input=True,            # default True
    guardrail_redact_output=False,          # default False
    guardrail_latest_message=True,          # evalúa solo el último mensaje del usuario (default False)
)
agent = Agent(system_prompt="You are a helpful assistant.", model=bedrock_model)
response = agent("Tell me about financial planning.")
if response.stop_reason == "guardrail_intervened":
    print("Content was blocked by guardrails, conversation context overwritten!")
```
Modo sombra: hook con `MessageAddedEvent` / `AfterInvocationEvent` que llama a `apply_guardrail` y solo registra.
- En **AgentCore**: Guardrails dentro de Policy en el Gateway; el harness aplica guardrails "through AgentCore gateway".

Precio (visto 15-nov-2026, por 1.000 *text units*; 1 text unit = hasta 1.000 caracteres): content filters texto $0.15; denied topics $0.15; PII $0.10; regex gratis; contextual grounding $0.10; Automated Reasoning $0.17 por política; imágenes $0.00075 por imagen.

## 8. IAM, regiones y cuotas esenciales

**IAM**
- Managed policy para usar AgentCore y su consola: **`BedrockAgentCoreFullAccess`** (amplia; solo desarrollo).
- Quien ejecuta `agentcore deploy` necesita: `sts:GetCallerIdentity`, leer los stacks `CDKToolkit` y `AgentCore-<project>-<target>`, bootstrap de CDK o asumir sus roles, y crear los recursos del proyecto (IAM, S3, ECR, CodeBuild, CloudWatch Logs, AgentCore).

Roles por defecto de la consola: `AmazonBedrockAgentCoreRuntimeDefaultServiceRole-*`.

- Perfiles de inferencia: IAM y SCP deben permitir **todas** las regiones destino; si un SCP bloquea una, la petición falla. No confíes solo en el prefijo: verifica con `aws bedrock get-inference-profile`.

## 11. Errores comunes y cómo probar sin gastar mucho

### Gotchas
1. **Id de modelo sin perfil**: los Claude 5.x en `bedrock-runtime` no tienen endpoint in-region (salvo Opus 5.5 en Londres). Usa `global.anthropic.claude-sonnet-5-5`.
2. **Default de Strands**: `Agent()` usa Claude Sonnet 4.6 en `us-west-2`. Define `model_id` y `region_name`.
3. **Ejemplos viejos en la propia doc de AWS**: el quickstart de Gateway usa `anthropic.claude-3-7-sonnet-20250219-v1:0`, el de LangGraph `us.anthropic.claude-3-5-haiku-20241022-v1:0`, el de observabilidad `global.anthropic.claude-sonnet-4-6`. No copies el id.
4. **`agentcore` equivocado**: el paquete pip `bedrock-agentcore-starter-toolkit` tapa al CLI de npm (sobre todo en Windows). Desinstálalo. No mezcles tutoriales del toolkit antiguo con el CLI v1.
5. **`agentcore create --name X` sin `--template`** crea un harness, no un agente en código.
6. **Session id corto**: `runtimeSessionId` necesita ≥ 33 caracteres.
7. **Estado en memoria**: `agent.messages` vive en la microVM; muere tras 15 min de inactividad o 8 h. Usa AgentCore Memory.
8. **Agente global compartido**: un `Agent` a nivel de módulo se reutiliza dentro de la sesión; para multiusuario crea el agente (o su session manager) por `session_id`/`actor_id` en el entrypoint.
9. **OAuth + boto3**: con auth JWT no sirve `invoke_agent_runtime` del SDK; hay que hacer HTTPS con bearer token.
10. **`prompt` no validado**: valida que sea `str` antes de pasarlo al agente.
11. **Policy en ENFORCE sin políticas**: todo queda denegado. La política necesita el ARN real del gateway (deploy primero).
12. **Memoria de largo plazo vacía**: la extracción es asíncrona y solo procesa eventos posteriores a que la estrategia esté `ACTIVE`; el namespace debe empezar y terminar con `/`.
13. **Prompt attack filter no mira tool results**: no detiene inyección indirecta que llega por una tool.
14. **Guardrails y Mantle**: `bedrock-mantle` no soporta Guardrails ni perfiles entre regiones.
15. **Trazas que no aparecen**: falta Transaction Search o no pasaron los ~10 minutos iniciales.
16. **Clientes boto3 a nivel de módulo en V2**: no reciben las credenciales con contexto de sesión.
17. **SCP por región**: un perfil `global.` falla si un SCP bloquea cualquiera de sus regiones destino.
18. **Graph/Swarm con session manager en agentes internos**: `ValueError`.
19. **Haiku 5.5 con prompts > 100K tokens**: toda la petición pasa a tarifa larga (5×).
20. **Contenedor x86**: Runtime exige ARM64.

### Probar gastando poco
- **Local y gratis**: `python my_agent.py` + `curl` a `http://localhost:8080/invocations`, o `agentcore dev --mode browser`. Solo pagas tokens del modelo.
- **Modelo barato**: `amazon.nova-micro-v1:0` ($0.035 / $0.14) o `global.anthropic.claude-haiku-5-5` ($0.10 / $0.50). Con Ollama (`OllamaModel`) el modelo es local y sin costo de tokens.
- **Runtime por consumo** (V1 $0.0895/vCPU-h + $0.00945/GB-h): una sesión de prueba de pocos minutos cuesta fracciones de centavo; baja `idleRuntimeSessionTimeout` o usa `StopRuntimeSession`.
- **CodeZip** (plantilla `agent-python-strands`) evita CodeBuild y ECR.
- **Gateway** $0.005 por 1.000 llamadas; **Identity** gratis vía Runtime/Gateway; **Memory** corto plazo por GB.
- **Limita el loop**: `limits={"turns": 5, "total_tokens": 10000}` en Strands; en Swarm baja `max_handoffs`.
- **Evita en pruebas**: Web Search ($7 por 1.000 consultas), Evaluations online con `--sampling-rate 1.0`, Managed Knowledge Base ($5.00 por GB-mes), modelos Fable/Opus.
- **Limpia siempre**: `agentcore remove all --yes` + `agentcore deploy --yes`. Revisa además log groups de CloudWatch y repos de ECR.
- **Créditos**: la página de precios de AgentCore dice "New AWS customers receive up to $200 in Free Tier credits".
- **Activa un presupuesto** en AWS Budgets antes de empezar (recomendación de este documento).
