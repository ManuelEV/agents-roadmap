### 2.4 Model router (L/openai/concepts/model-router, 2026-10-30)

- "A trained language model that intelligently routes your prompts in real time to the most suitable large language model". Se despliega como cualquier modelo: nombre `model-router`, versión `2025-11-18` (GA).
- Deployment types: Global Standard y Data Zone Standard.
- Modos: **Balanced** (por defecto; modelos dentro de ~1–2% de la mejor calidad, elige el más barato), **Cost** (banda ~5–6%), **Quality**.
- Subconjunto de modelos configurable; ese subconjunto es también el conjunto de failover (elige al menos dos).
- Enruta entre modelos OpenAI, Anthropic, xAI, DeepSeek, Meta y Fireworks. Los modelos Claude deben desplegarse antes en la misma cuenta con SKU equivalente o falla con `InvalidResourceProperties`.
- La ventana efectiva "is limited by the smallest underlying model".
- Con agentes: se elige el deployment del router como modelo del agente; cada request se enruta por separado y el campo `model` de la respuesta dice quién respondió. En la tabla de tools de Agent Service, `model-router` figura con "No" para A2A, Azure AI Search, Azure Functions, Computer Use, Image Generation y Web Search.

### 2.5 Deployment types (L/foundry-models/concepts/deployment-types, 2026-08-06)

`GlobalStandard` (recomendado para empezar: lanza primero, precio más bajo, mayor cuota), `DataZoneStandard` (US/EU/APAC), `Standard` (regional), `GlobalProvisionedManaged` / `DataZoneProvisionedManaged` / `ProvisionedManaged` (PTU reservadas), `GlobalBatch` / `DataZoneBatch` (asíncrono, 50% de descuento), `DeveloperTier` (solo evaluación de modelos fine-tuned). *Priority processing* y *Flex* son niveles de servicio por request (`service_tier`), no tipos de despliegue.

### 3.2 Instalación y agente mínimo


Agente con una function tool. Adaptado de AF/overview/ (2026-10-23) y AF/agents/tools/function-tools (2026-10-22):

```python
import asyncio
from typing import Annotated

from agent_framework import Agent, tool
from agent_framework.foundry import FoundryChatClient
from azure.identity import AzureCliCredential
from pydantic import Field


@tool(approval_mode="never_require")
def get_weather(
    location: Annotated[str, Field(description="The location to get the weather for.")],
) -> str:
    """Get the weather for a given location."""
    return f"The weather in {location} is cloudy with a high of 15°C."


agent = Agent(
    client=FoundryChatClient(
        project_endpoint="https://your-foundry-service.services.ai.azure.com/api/projects/your-foundry-project",
        model="gpt-5.4-mini",            # nombre de TU deployment
        credential=AzureCliCredential(),
    ),
    name="WeatherAgent",
    instructions="You are a helpful weather assistant.",
    tools=[get_weather],
)


async def main() -> None:
    result = await agent.run("What is the weather like in Amsterdam?")
    print(result.text)


asyncio.run(main())
```

Notas verificadas:

- "Agent Framework does **not** automatically load `.env` files": llama a `load_dotenv()` tú mismo.
- `FoundryChatClient(credential=...)` sin más argumentos lee `FOUNDRY_PROJECT_ENDPOINT` y `FOUNDRY_MODEL` del entorno.
- Sin `@tool`, cualquier función Python sirve: el esquema sale del nombre, el docstring y los type hints.
- `approval_mode="never_require"` es para ejemplos; la doc recomienda `"always_require"` en producción.
- Contexto solo-runtime: parámetro `ctx: FunctionInvocationContext` (oculto al modelo) y `agent.run(..., function_invocation_kwargs={"user_id": "user_123"})`.
- Límites del loop: `client.function_invocation_configuration.update({"max_iterations": 5, "max_function_calls": 20, "max_duration_seconds": 30.0})`.
- Otros clientes: `OpenAIChatClient`, `OpenAIChatCompletionClient` (`agent_framework.openai`); atajo `client.as_agent(instructions=..., tools=...)`.
- Equivalente .NET: `new AIProjectClient(new Uri(endpoint), new AzureCliCredential()).AsAIAgent(model: "gpt-5.4-mini", instructions: "...")` y `await agent.RunAsync("...")`.

```python
response_stream = agent.run("Tell me a story", stream=True)   # devuelve ResponseStream

async for update in response_stream:        # cada update es un AgentResponseUpdate
    if update.text:
        print(update.text, end="", flush=True)

final = await response_stream.get_final_response()   # AgentResponse agregado
print(final.text, len(final.messages))
```

- `AgentResponse`: `.text`, `.messages` (cada `Message` tiene `.role`, `.text`, `.contents`).
- `AgentResponseUpdate`: `.text`, `.contents`.
- Todo contenido es la clase `Content`, discriminada por `content.type`: `"text"`, `"text_reasoning"`, `"data"`, `"uri"`, `"error"`, `"function_call"`, `"function_result"`, `"usage"`, `"mcp_server_tool_call"`, `"mcp_server_tool_result"`, `"function_approval_request"`, `"function_approval_response"`, `"oauth_consent_request"`, entre otros.
- Si puedes cortar antes de tiempo, usa `async with response_stream:` para cerrar el stream del proveedor.
- Opciones por run: `agent.run(..., options={"temperature": 0.3, "max_tokens": 150})`; `tools` e `instructions` van como argumentos directos, no dentro de `options`.
- En .NET: `RunStreamingAsync` devuelve `AgentResponseUpdate` con `.Text` y `.Contents`.

### 3.5 Middleware (AF/concepts/agents/middleware/, 2026-10-22)

Tres tipos: **agent** (`AgentContext`), **function** (`FunctionInvocationContext`) y **chat** (`ChatContext`). `call_next()` no recibe argumentos: se muta el contexto compartido.

```python
from collections.abc import Awaitable, Callable
from agent_framework import AgentContext, AgentMiddleware, AgentResponse, Message

class SecurityAgentMiddleware(AgentMiddleware):
    async def process(self, context: AgentContext, call_next: Callable[[], Awaitable[None]]) -> None:
        last_message = context.messages[-1] if context.messages else None
        if last_message and last_message.text and "password" in last_message.text.lower():
            context.result = AgentResponse(
                messages=[Message("assistant", ["Detected sensitive information, the request is blocked."])]
            )
            return                      # no llamar a call_next() corta la ejecución
        await call_next()

agent = Agent(client=client, instructions="...", middleware=[SecurityAgentMiddleware()])
```

- También por función con decoradores `@agent_middleware`, `@function_middleware`, `@chat_middleware`.
- Registro a nivel agente (`Agent(middleware=[...])`) o por run (`agent.run(..., middleware=[...])`). Orden: agente (externo) → run (interno) → ejecución.
- Terminar: asignar `context.result` y lanzar `MiddlewareTermination`.
- El chat middleware corre en **cada** llamada al modelo dentro del loop de tools.
- **Agent Hooks** (`create_agent_hooks_middleware`, paquete `agent-hooks-sdk`): plano de control *fail-closed* con veredictos allow/deny/transform. Experimental, solo Python (AF/agents/agent-hooks, 2026-09-15).

### 3.8 Workflows en grafo

Fuentes: AF/concepts/workflows/builder-and-execution, /executors, /events (2026-10-22) y /edges (2026-10-15).

```python
from typing_extensions import Never
from agent_framework import Executor, WorkflowBuilder, WorkflowContext, handler, executor

class UpperCase(Executor):
    @handler
    async def to_upper_case(self, text: str, ctx: WorkflowContext[str]) -> None:
        await ctx.send_message(text.upper())          # mensaje al siguiente nodo

@executor(id="reverse_text")
async def reverse_text(text: str, ctx: WorkflowContext[Never, str]) -> None:
    await ctx.yield_output(text[::-1])                # salida del workflow

upper = UpperCase(id="upper_case")
workflow = WorkflowBuilder(start_executor=upper).add_edge(upper, reverse_text).build()

async for event in workflow.run("hello", stream=True):
    if event.type == "output":
        print(f"Workflow completed: {event.data}")

events = await workflow.run("hello")                  # sin streaming
print(events.get_outputs())
```

- Modelo de ejecución: "modified Pregel", por *supersteps*; los executors de un mismo superstep corren en paralelo.
- Aristas: `add_edge(a, b)`, condicional `add_edge(a, b, condition=fn)`, `add_fan_in_edges([w1, w2], agregador)`, `add_switch_case_edge_group(origen, [Case(condition=..., target=...), Default(target=...)])`, `add_multi_selection_edge_group(origen, [...], selection_func=...)`.
- Eventos: **una sola clase** `WorkflowEvent` con `type` string: `"started"`, `"status"`, `"output"`, `"intermediate"`, `"failed"`, `"error"`, `"warning"`, `"executor_invoked"`, `"executor_completed"`, `"executor_failed"`, `"superstep_started"`, `"superstep_completed"`, `"request_info"`. Campos usados: `event.type`, `event.data`, `event.executor_id`, `event.request_id`.
- Un workflow se puede envolver como agente con `.as_agent()`.
- API funcional (`@workflow`, `@step`, `RunContext`): **experimental**, solo Python.

Checkpoints (AF/workflows/checkpoints, 2026-09-16):

```python
from agent_framework import InMemoryCheckpointStorage, WorkflowBuilder

checkpoint_storage = InMemoryCheckpointStorage()
workflow = WorkflowBuilder(start_executor=start, checkpoint_storage=checkpoint_storage).add_edge(start, b).build()

checkpoints = await checkpoint_storage.list_checkpoints(workflow_name=workflow.name)
async for event in workflow.run(checkpoint_id=checkpoints[-1].checkpoint_id, stream=True):
    ...
```

Almacenes: `InMemoryCheckpointStorage`, `FileCheckpointStorage(storage_path=...)`, `CosmosCheckpointStorage` (`agent-framework-azure-cosmos --pre`). Se guarda al final de cada superstep. Hooks de estado: `on_checkpoint_save` / `on_checkpoint_restore`.

Human-in-the-loop (AF/workflows/human-in-the-loop, 2026-07-16):

```python
from agent_framework import Executor, WorkflowBuilder, WorkflowContext, handler, response_handler

class JudgeExecutor(Executor):
    @handler
    async def handle_guess(self, guess: int, ctx: WorkflowContext[int, str]) -> None:
        if guess == 42:
            await ctx.yield_output("found!")
        else:
            await ctx.request_info(request_data=NumberSignal(hint="try again"), response_type=int)

    @response_handler
    async def on_human_response(self, original_request: NumberSignal, response: int,
                                ctx: WorkflowContext[int, str]) -> None:
        await self.handle_guess(response, ctx)

# lado del llamador
pending: dict[str, int] = {}
async for event in workflow.run(25, stream=True):
    if event.type == "request_info":
        pending[event.request_id] = 42            # respuesta del humano
async for event in workflow.run(stream=True, responses=pending):
    ...
```

`NumberSignal` es un tipo propio del ejemplo. Las solicitudes pendientes se guardan en los checkpoints y se reemiten al restaurar; se puede pasar `checkpoint_id` y `responses` juntos. La aprobación de tools dentro de un workflow llega como `request_info` con `event.data.type == "function_approval_request"`.

### 3.9 Orquestaciones multiagente (AF/workflows/orchestrations/*, oct-2026)

Todos los builders se importan de `agent_framework.orchestrations` (paquete `agent-framework-orchestrations`) y se configuran por argumentos del constructor + `.build()`.

```python
from agent_framework.orchestrations import (
    SequentialBuilder, ConcurrentBuilder, HandoffBuilder, GroupChatBuilder, MagenticBuilder,
)

# Secuencial
workflow = SequentialBuilder(participants=[writer, reviewer]).build()
events = await workflow.run("Write a tagline for a budget-friendly eBike.")
final = events.get_outputs()[0]                   # AgentResponse

# Concurrente (opcional: .with_aggregator(fn))
workflow = ConcurrentBuilder(participants=[researcher, marketer, legal]).build()

# Handoff (solo participantes Agent; malla por defecto)
workflow = (
    HandoffBuilder(name="customer_support_handoff",
                   participants=[triage_agent, refund_agent, order_agent])
    .with_start_agent(triage_agent)
    .build()
)

# Group chat
workflow = GroupChatBuilder(
    participants=[researcher, writer],
    termination_condition=lambda conversation: len(conversation) >= 4,
    selection_func=round_robin_selector,          # o orchestrator_agent=...
).build()

# Magentic
workflow = MagenticBuilder(
    participants=[researcher_agent, coder_agent],
    manager_agent=manager_agent,
    max_round_count=10, max_stall_count=3, max_reset_count=2,
).build()
```

- Handoff pide input al usuario con `request_info` y `HandoffAgentUserRequest`; se responde con `HandoffAgentUserRequest.create_response(texto)` y `workflow.run(responses=..., stream=True)`.

### 4.4 Hosted agents

Datos de plataforma (L/agents/concepts/hosted-agents, 2026-11-09):

- Sandbox aislado por VM **por sesión**, con `$HOME` y `/files` persistentes. Tamaños documentados: 0,5 vCPU/1 GiB, 1 vCPU/2 GiB, 2 vCPU/4 GiB. Disco por sesión hasta 20 GiB.
- Idle timeout configurable de 2 a 240 minutos (15 por defecto). La sesión se borra tras 30 días de inactividad.
- Cada versión es inmutable; el endpoint sirve el 100% a una versión (sin *traffic splitting*).
- Lenguajes: Python y C#. Disponible en 31 regiones (entre ellas East US, East US 2, Sweden Central, West Europe, Brazil South).
- Estado: *sessions* (cómputo + archivos), *conversations* (historial en Foundry) y *state store* (clave-valor durable, 30 días por defecto).

```python
from agent_framework import Agent
from agent_framework.foundry import FoundryChatClient
from agent_framework_foundry_hosting import ResponsesHostServer
from azure.identity import DefaultAzureCredential

def main() -> None:
    client = FoundryChatClient(
        project_endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
        model=os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"],
        credential=DefaultAzureCredential(),
    )
    agent = Agent(
        client=client,
        instructions="You are a friendly assistant. Keep your answers brief.",
        default_options={"store": False},
    )
    server = ResponsesHostServer(agent)
    server.run()                       # escucha en el puerto 8088

if __name__ == "__main__":
    main()
```

Prueba local: `curl -X POST http://localhost:8088/responses -H "Content-Type: application/json" -d '{"input":"Hello","stream":false}'`. Con código propio sin framework: `ResponsesAgentServerHost` de `azure.ai.agentserver.responses`.

Despliegue con `azd` (L/agents/quickstarts/quickstart-hosted-agent, 2026-10-26):

- Modos: `--deploy-mode code` (ZIP, sin Docker; por defecto en Python y .NET) o `container` (Dockerfile).
- Un solo `azure.yaml` en la raíz (no hay `agent.yaml`): servicio `host: azure.ai.project` con `deployments`, y servicio `host: azure.ai.agent` con `kind: hosted`, `protocols: [{protocol: responses, version: 2.0.0}]`, `startupCommand`, `env` y `container.resources`.
- Agentes Python necesitan `PYTHONNOUSERSITE: "1"` en `env`. No declares `FOUNDRY_PROJECT_ENDPOINT`: lo inyecta la plataforma.
- Recursos que se crean: Foundry account + proyecto (con managed identity), deployment del modelo, Azure Container Registry, Application Insights, Log Analytics workspace.
- Roles: `Foundry Project Manager` en el proyecto existente, u `Owner` del resource group para crear uno nuevo.
- Con el SDK: `project_client.agents.create_version_from_code(agent_name=..., definition=HostedAgentDefinition(cpu="0.5", memory="1Gi", code_configuration=..., protocol_versions=[ProtocolVersionRecord(protocol="responses", version="2.0.0")]), code=...)`.

### 4.7 A2A entrante (L/agents/how-to/enable-agent-to-agent-endpoint, 2026-09-11)

- A2A v1.0 GA, v0.3 preview. Sin selector de versión, Foundry sirve **v0.3**; pedir v1.0 con el header `A2A-Version: 1.0`.
- Limitaciones: solo JSON-RPC, solo texto, **sin streaming**. No se configura en el portal (REST o SDK).
- Quien llama necesita `Foundry Agent Consumer` y token Entra con scope `https://ai.azure.com/.default`.
- Agent card: `.../agents/{agent}/endpoint/protocols/a2a/agentCard/v1.0`.
- Activar: `PATCH $BASE_URL/agents/$AGENT_NAME?api-version=v1` con `agent_card` y `"agent_endpoint": {"protocol_configuration": {"responses": {}, "a2a": {}}}`.

## 5. Identidad y gobierno

### 5.1 Microsoft Entra Agent ID (GA)

- "An identity and security framework that extends Microsoft Entra capabilities to AI agents" (learn.microsoft.com/en-us/entra/agent-id/what-is-microsoft-entra-agent-id, 2026-04-14).
- Conceptos (…/entra/agent-id/key-concepts, 2026-04-03):
  - **Agent identity blueprint**: plantilla que guarda las credenciales y obtiene tokens para sus agent identities; las políticas (p. ej. Conditional Access) se heredan.
  - **Agent identity**: la identidad con la que el agente se autentica; no tiene credenciales propias.
  - **Agent's user account**: cuenta opcional 1:1, solo si el agente debe acceder a sistemas que exigen un objeto usuario.
- Patrones: interactivo (permisos delegados, flujo OBO) y autónomo (identidad propia, client credentials).
- Licencia: Agent ID está disponible para todos los clientes de Entra; extender funciones de seguridad a agentes requiere **Microsoft Agent 365** (incluido en Microsoft 365 E7; add-on para E5/A5/Business Premium).

### 5.2 Identidad de agentes en Foundry (L/agents/concepts/agent-identity, 2026-10-28)

- "Creating an agent provisions a unique agent blueprint and the identity for its default instance."
- **"A newly created agent identity starts without resource permissions."** Hay que asignar RBAC a mano: `az role assignment create` con el object ID de la agent identity, idealmente a nivel de recurso o resource group.
- Sin secretos: Foundry crea una *federated identity credential* en el blueprint.
- Dos modelos: *application-only* (autoridad del agente) y *delegated* (en nombre del usuario). La delegación ("User delegation for tools", tipos `AgentOnBehalfOfUser`, `UserEntraToken`) está **en preview**.
- En hosted agents, la managed identity del proyecto no está disponible para tu código; el agente usa su propia identidad.
- Migrar de la identidad compartida legacy cambia la identidad: las asignaciones de rol **no se transfieren**.

### 5.3 Roles RBAC (L/concepts/rbac-foundry, 2026-09-16)

| Rol | Para qué | ID |
|---|---|---|
| `Foundry Agent Consumer` | Solo invocar endpoints de agentes (mínimo privilegio para consumidores). | `eed3b665-ab3a-47b6-8f48-c9382fb1dad6` |
| `Foundry User` | Construir y probar agentes (mínimo privilegio para desarrolladores). | `53ca6127-db72-4b80-b1b0-d745d6d5456d` |
| `Foundry Project Manager` | Gestionar proyectos y **publicar agentes**. | `eadc314b-1a2d-4efa-be10-5d325db5065e` |
| `Foundry Account Owner` | Crear cuentas/proyectos y gestionar modelos; **no** puede construir ni invocar. | `e47c6f54-e4a2-4754-9501-8e0985b135e1` |
| `Foundry Owner` | Todo. | `c883944f-8b7b-4483-af10-35834be79c4a` |

- La doc recomienda usar el GUID en lugar del nombre mientras dura el renombre.
- `Owner` y `Contributor` de Azure **no** incluyen acciones de plano de datos: no pueden crear agentes.
- No uses roles que empiecen con "Cognitive Services" ni "Azure AI Developer".
- La autenticación por API key "grants full access without role restrictions"; además, agentes y evaluaciones exigen Entra ID.
- Hosted agents (L/agents/concepts/hosted-agent-permissions, 2026-04-21): la managed identity del proyecto necesita `Foundry User` en la cuenta y `Container Registry Repository Reader` (o `AcrPull`) en el ACR; quien despliega, `Container Registry Repository Writer` (o `AcrPush`).

### 5.4 Foundry Control Plane, Agent 365 y AI Gateway

- **Foundry Control Plane** (L/control-plane/overview, 2026-05-06; preview): botón **Operate** arriba a la derecha. Paneles **Overview**, **Assets** (agentes, modelos y tools de toda la suscripción) y **Compliance** (políticas de guardrails; integraciones con Azure Policy, Defender y Purview).
- **Agent 365** (learn.microsoft.com/en-us/microsoft-agent-365/overview, 2026-11-11): "the observability platform for AI"; registro de agentes en el Microsoft 365 admin center (**Agents > All agents**). GA para el segmento Commercial, licencia por usuario.
- **AI Gateway** (L/configuration/enable-ai-api-management-gateway-portal, 2026-08-03; preview): **Manage > AI Gateway > Add AI Gateway**; usa Azure API Management (crea una instancia Basic v2). Límites de tokens por proyecto: superar TPM devuelve `429`, superar la cuota `403`.
- Políticas de APIM (learn.microsoft.com/en-us/azure/api-management/genai-gateway-capabilities, 2026-05-29): `llm-token-limit`, `llm-emit-token-metric`, `llm-semantic-cache-lookup` / `llm-semantic-cache-store`, `llm-content-safety`. APIM también expone APIs REST como servidores MCP, hace passthrough a servidores MCP existentes e importa APIs de agentes A2A (solo JSON-RPC).

### 5.5 Aislamiento de red (L/agents/how-to/virtual-networks, 2026-06-15)

- Oferta: "Standard Setup with private networking". Exige traer Storage, AI Search y Cosmos DB propios.
- Subred delegada a `Microsoft.App/environments`, tamaño `/27` o mayor (`/24` recomendado en producción).
- Limitaciones clave: la inyección de red para hosted agents **debe configurarse al crear la cuenta** (no se puede añadir después); el recurso Foundry debe estar en la misma región que la VNet; File Search con archivos de Blob Storage no está soportado; ACR privado solo para proyectos creados después del 25-jun-2026.

## 6. Guardrails

Fuente: L/guardrails/guardrails-overview (2026-10-20). "**Agent guardrails are in preview.**"

- Un *guardrail* es "a named collection of controls". Cada control define un riesgo, puntos de intervención y una acción.
- Cuatro puntos de intervención: **User input**, **Tool call** (preview, solo agentes), **Tool response** (preview, solo agentes), **Output**. Cada punto añade ~50–100 ms de latencia.

| Riesgo | Modelos | Agentes (preview) |
|---|---|---|
| Hate, Sexual, Self-harm, Violence | Sí | Sí |
| User prompt attacks (jailbreak) | Sí | Sí |
| Indirect attacks (XPIA) | Sí | Sí |
| Protected material (texto y código) | Sí | Sí |
| Personally identifiable information (preview) | Sí | Sí |
| Task Adherence (preview) | Sí | Sí |
| Spotlighting (preview) | Sí | **No** |
| Groundedness (preview) | Sí | **No** |

- Acciones: *Annotate* (solo modelos) y *Annotate and block*. Niveles: Off, Low, Medium, High.
- Por defecto los modelos llevan el guardrail **`Microsoft.DefaultV2`**: categorías de daño en umbral Medium, jailbreak en prompts y protected material en respuestas. "Document attack detection is off by default and must be enabled."
- "The agentic guardrail fully overrides the model's guardrail." Sin guardrail propio, el agente hereda el de su deployment.
- Moderación de tool call/response solo para: Azure AI Search, Azure Functions, OpenAPI, SharePoint Grounding, Fabric Data Agent, Bing Grounding, Bing Custom Search, Browser Automation. **MCP y function tools no están en esa lista.**
- Aplica solo a agentes de Foundry Agent Service, no a agentes externos registrados en el Control Plane.

Configurar (L/guardrails/how-to-create-guardrails, 2026-10-15):

- Crear: portal > **Build** > **Guardrails** > **Create Guardrail** (añadir controles → **Add agents** / **Add models** → revisar y crear). Requiere `Foundry Account Owner` o superior.
- Asignar desde el agente: **Build** > **Agents** > agente > sección **Guardrails** > **Manage** > **Assign a new guardrail** > **Assign**.
- Por REST un guardrail es una "RAI policy" de ARM; en un deployment de modelo va en la propiedad `raiPolicyName`.

Hosted agents (L/agents/how-to/add-hosted-agent-guardrails, 2026-09-24):

```python
HostedAgentDefinition(..., rai_config=RaiConfig(rai_policy_name=RAI_POLICY_ID))
# RAI_POLICY_ID = "/subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.CognitiveServices/accounts/<account>/raiPolicies/<policy>"
```

- "When you omit `rai_config`, the agent runs without a content safety guardrail."
- Un ID de política inexistente **falla en abierto** (sin filtrado).
- Un prompt bloqueado devuelve HTTP 400 con código `content_filter`.

Azure AI Content Safety como API independiente (para agentes fuera de Foundry). Prompt Shields (learn.microsoft.com/en-us/azure/ai-services/content-safety/quickstart-jailbreak, 2026-01-30):

```bash
curl --location --request POST '<endpoint>/contentsafety/text:shieldPrompt?api-version=2024-09-01' \
--header 'Ocp-Apim-Subscription-Key: <your_subscription_key>' \
--header 'Content-Type: application/json' \
--data-raw '{
  "userPrompt": "Your input text here",
  "documents": ["Document text to analyze"]
}'
# {"userPromptAnalysis": {"attackDetected": true}, "documentsAnalysis": [{"attackDetected": false}]}
```

Precios: dentro de Foundry, "free moderation on the first 1000 text characters". El servicio independiente tiene un nivel gratuito de 5.000 registros de texto al mes; un registro son hasta 1.000 caracteres. Los precios del nivel Standard no fueron visibles (`$-`).

## 7. Evaluación y observabilidad

### 7.1 Evaluadores de agentes (L/concepts/evaluation-evaluators/agent-evaluators, 2026-09-30)

- Sistema: Task Completion, Task Adherence, Intent Resolution, Customer Satisfaction (todos preview), Task Navigation Efficiency.
- Proceso: Tool Call Accuracy, Tool Selection, Tool Input Accuracy, Tool Output Utilization, Tool Call Success.
- IDs impresos en la página: `builtin.task_adherence`, `builtin.task_navigation_efficiency`, `builtin.output_quality`, `builtin.tool_use_quality`.
- Soporte limitado para tools como Azure AI Search, Bing Grounding, Code Interpreter y Web Search.

**El camino actual son evaluaciones en la nube** con `azure-ai-projects` + la API de evals de OpenAI, no los evaluadores locales. `azure-ai-evaluation` (1.18.12 [resumen]) sigue existiendo para evaluación local y red teaming local.

Adaptado de L/observability/how-to/evaluate-agent (2026-10-01):

```python
import os, time
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import TestingCriterionAzureAIEvaluator
from openai.types.eval_create_params import DataSourceConfigCustom

endpoint = os.environ["AZURE_AI_PROJECT_ENDPOINT"]
model_deployment = os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"]
AGENT_NAME = "my-agent"

project_client = AIProjectClient(endpoint=endpoint, credential=DefaultAzureCredential())
client = project_client.get_openai_client()

# test-queries.jsonl: una línea por caso, p. ej. {"query": "What's the weather in Seattle?"}
dataset = project_client.datasets.upload_file(name="agent-test-queries", version="1", file_path="./test-queries.jsonl")

testing_criteria = [
    TestingCriterionAzureAIEvaluator(
        type="azure_ai_evaluator", name="task_adherence", evaluator_name="builtin.task_adherence",
        initialization_parameters={"deployment_name": model_deployment},
        data_mapping={"query": "{{item.query}}", "response": "{{sample.output_items}}"},
    ),
]

evaluation = client.evals.create(
    name="Agent Quality Evaluation",
    data_source_config=DataSourceConfigCustom(
        type="custom",
        item_schema={"type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"]},
        include_sample_schema=True,
    ),
    testing_criteria=testing_criteria,
)

eval_run = client.evals.runs.create(
    eval_id=evaluation.id,
    name="Agent Evaluation Run",
    data_source={
        "type": "azure_ai_target_completions",
        "source": {"type": "file_id", "id": dataset.id},
        "input_messages": {"type": "template", "template": [
            {"type": "message", "role": "user", "content": {"type": "input_text", "text": "{{item.query}}"}}]},
        "target": {"type": "azure_ai_agent", "name": AGENT_NAME},
    },
)

while True:
    run = client.evals.runs.retrieve(run_id=eval_run.id, eval_id=evaluation.id)
    if run.status in ["completed", "failed"]:
        break
    time.sleep(5)
print(run.status, run.report_url)
```

`pip install "azure-ai-projects>=2.8.0"`. Combiné el criterio `builtin.task_adherence` de la página de evaluadores con el flujo de la guía (que usa además un evaluador de rúbrica generado). `{{sample.output_items}}` es la salida estructurada del agente con sus tool calls; `{{sample.output_text}}` es solo el texto.

## 12. Errores comunes y cómo probar sin gastar

### Errores comunes

1. **Usar nombres de rol viejos.** `Azure AI User` ahora es `Foundry User`. En scripts, usa el GUID.
2. **Creer que `Owner` alcanza.** `Owner`/`Contributor` no tienen acciones de plano de datos: sin `Foundry User` no puedes crear agentes.
3. **Mezclar SDKs.** `azure-ai-projects` 1.x, `azure-ai-agents` y la Assistants API (threads/runs) son la generación anterior. Usa `azure-ai-projects` 2.x.
4. **Usar API key con agentes.** Agentes y evaluaciones exigen Entra ID (`az login` + `DefaultAzureCredential`).
5. **Confundir nombre de deployment con nombre de modelo.** El parámetro `model` es el nombre de **tu** deployment.
6. **Crear el recurso sin `--assign-identity`.** Falla la creación del proyecto.
7. **Olvidar que la identidad del agente nace sin permisos.** Hay que asignarle RBAC para acceder a Storage, bases, etc.
8. **Asumir que los guardrails protegen todo.** En agentes están en preview; no moderan tool calls de MCP ni de function tools; Claude no trae filtro; un hosted agent sin `rai_config` corre sin guardrail; una política inexistente falla en abierto.
9. **Dejar `approval_mode` de MCP sin `default`.** Las tools no listadas no piden aprobación.
10. **Olvidar `load_dotenv()`.** Agent Framework no carga `.env` solo.
11. **Elegir `gpt-5-mini` y esperar function calling en Agent Service.** La tabla de tools lo limita; revisa el filtro del catálogo.
12. **Construir sobre lo que se retira.** Workflows del portal (1-dic-2026), familia `o*` (19-nov-2026), `gpt-4o`/`gpt-4.1` (abril 2027), APIs de memoria legacy de Agent Framework (después del 31-dic-2026).
13. **Sobredimensionar hosted agents.** CPU y memoria son **por sesión**: el costo se multiplica por la concurrencia.
14. **Esperar streaming en A2A entrante** o que sirva v1.0 por defecto (sirve v0.3 sin el header).
15. **Fijar versiones de Agent Framework a la ligera.** Hay release semanal con cambios *breaking* frecuentes; fija la versión en `requirements.txt`.
16. **Pasar IDs del servicio desde el cliente** (`previous_response_id`, `conversation`) sin verificar al dueño.

### Cómo probarlo sin gastar mucho

- **Sin Azure**: Agent Framework funciona con `OpenAIChatClient` (API de OpenAI) u Ollama; DevUI y los workflows corren en local. Foundry Local da inferencia en el dispositivo sin suscripción.
- **Prompt agents en vez de hosted**: no pagan cómputo, solo tokens y tools.
- **Modelos baratos**: `gpt-5-nano` (0,05 / 0,40) o `gpt-5.4-nano` (0,20 / 1,25) por 1M de tokens [API de precios, re-verificar].
- **Basic setup**: evita Cosmos DB (mínimo 3.000 RU/s), AI Search y Storage propios del standard setup.
- **Hosted agents**: usa el tamaño mínimo y baja el idle timeout (mínimo 2 minutos); escalan a cero. Referencia: ~0,10 US$/hora de vCPU [API de precios].
- **Apaga las evaluaciones del playground**, que vienen activas y se facturan.
- **Capacidad mínima** en el deployment (`--sku-capacity 10` en los ejemplos) para acotar el consumo.
- **Limpia siempre**: `azd down` o borrar el resource group. Ojo: Application Insights y Log Analytics cobran por ingesta.
- La suscripción de prueba gratuita (Tier 0) solo tiene cuota para `gpt-4.1-mini`, `gpt-5-mini`, `o4-mini` y embeddings, y no puede usar Claude.
